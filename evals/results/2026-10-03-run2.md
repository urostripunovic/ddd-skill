# Run 2 of 2026-10-03

Run against the revised kit (eight skills, twenty cards) and the revised fixtures. Five sub-agents, one run each, each in its own git worktree at the head commit. The two reviewers were given only their skill file path, the worktree path and the pinned hashes. The baseline was given the prompt in `baseline-prompt.md` and no skill.

Not run: `task-review` (the fixture has no task), `ddd-review-all`, and the interview eval.

**The seeds do not separate the skills from no skill.** A plain "review this diff against the model" prompt caught 32 of 33. So this fixture shows that the reviewers do not miss obvious problems, and nothing more. It cannot show what the skills add.

**The baseline was not free of the kit.** Its checkout contained `docs/ddd/cards/`, `tools/` and the lint configs, and it used them: it ran `tools/check-model.sh` and the linters and proposed card corrections. A baseline that measures the kit as a whole needs a checkout without those.

## What this run showed about the kit

- ~~**`gochecksumtype` under golangci-lint does not check a switch in another package than the one declaring the sum type.**~~ Withdrawn; see the correction below.
- **The security reviewer reports weak model rules as code findings.** It should say "the model's rule is too weak" once, and point to the model review.
- **Zero values:** the skill and the answer key disagree on whether an unchecked zero-value primitive is a finding.
- **The eval needs harder seeds.** The "findings beyond the seeds" from both runs are the source: a secret leaking through a wrapped error, a quote for the wrong product, a defensive copy with no test, a lint rule that silently does not apply.

## Caveats

- One run each. No measure of variance.
- The reviewers and the baseline are the same model family that wrote the skills and the fixtures.
- Scoring was by hand, by the same model.
- The fixes to the clean fixture have not been reviewed by a second run.

## Correction of 2026-10-08

The cross-package lint finding does not reproduce. On the clean fixture, with a fourth state `ShippedOrder` added and a switch over `Order` in `internal/app`, golangci-lint v2.14.0 reported all three switches with `gochecksumtype`, the one in `internal/app` included; the standalone `go-check-sumtype` did the same. What the run observed is not known: perhaps an older linter version, a stale lint cache or a mistake in the attempt.

The rule it added ("keep every switch over a sum type in the declaring package") is removed from cards 03 and 06, and the fixture's narrowing switches are back in the workflow package. The finding is counted against the reviewer: a candidate false positive that was accepted without a second check. Before a finding changes the kit, reproduce it in a run separate from the one that reported it.
