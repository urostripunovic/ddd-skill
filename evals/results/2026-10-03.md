## Findings beyond the seeds

Real problems in the fixture that were not planted on purpose:

- The API key leaks through the wrapped transport error, because `*url.Error` carries the full URL.
- The raw SKU string allows query-parameter injection in the pricing call, and an HTTP 500 is treated as a successful quote.
- Cancelling twice overwrites the reason.
- `Load` never reads lines, so every reloaded order is empty.
- The TypeScript `addLine` accepts an order in any state, and takes the unit price from the request body.
- Go and TypeScript validate SKUs differently, so one primitive has two rule sets.

## What the run showed about the kit

- **Overlap remains.** Four areas were reported by both reviewers: the model edited after approval, JSON tags on a domain type, the empty-order rule, and raw primitives. Each reviewer said the other owned the item, so the merge step in `ddd-review-all` has to deduplicate these.
- **golangci-lint reported a Go file inside `node_modules`.** The reference config now excludes that directory.
- **The model template had no place for use-case failures or outside facts.** The DDD reviewer reported both as gaps in the model. The template now has a table for each.
- **The untracked `package-lock.json` showed up in both cleanup checks.** The fixture now ignores it.
